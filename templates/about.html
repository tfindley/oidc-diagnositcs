Zero-knowledge sessions

Token data is stored on the server as encrypted ciphertext. The encryption key for your session is split between two places:

  • A random per-session key that lives only in your browser cookie.
  • A server-held pepper that is the same for every user.

Both halves are required to decrypt session data. Your cookie alone cannot decrypt anyone else's session. The server alone cannot decrypt any session — even an admin reading the disk directly sees only opaque bytes. Decrypted plaintext exists in server memory only for the brief duration of handling a request that includes your cookie.

Disk files are removed when you sign out. They also become unreadable once the configured session lifetime expires (SESSION_LIFETIME_MINUTES), independent of the JWT's own expiry — the nav bar shows both countdowns side-by-side.

What the operator's server processes

The server code receives and decodes your tokens in order to render them for display. It does not log token values.

Debug mode breaks the privacy model. With FLASK_DEBUG=true the Werkzeug debugger and tracebacks can surface the server pepper, secret key, and in-flight plaintext session data. A properly configured instance keeps debug mode off.

Your password is never seen by this tool — you authenticate directly on your OIDC provider's login page.

Third parties

This tool does not connect to any analytics, advertising, or tracking service. The only outbound network calls it makes are to your configured OIDC provider.

Trust the operator. As with any OAuth2 client, you are trusting the person who runs this instance. Only sign in with accounts whose data you are comfortable sharing with the instance operator. Use the minimum scopes you need (openid email profile is sufficient for most diagnostic purposes).
